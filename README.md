## About

I am an environmental policy researcher pursuing a Master of Environmental Policy (iMEP) at Duke University, with study at both the Durham and Kunshan campuses. My work sits at the intersection of **environmental and land-use economics**, **energy and climate policy**, and **urban environmental measurement**. I use causal inference and spatial methods to study how economic shocks, regulation, and policy interventions reshape land use and environmental outcomes.

I am applying to fully-funded PhD programs (Fall 2027) in environmental and land-use economics, public policy, geography, environmental science, and ecology, and adjacent cross-disciplinary programs worldwide.

## 小红书收藏知识库

**Why I built it.** I save hundreds of 小红书 notes a month &mdash; research leads, methods references, writing tips. After a year, "searching bookmarks" became useless. I needed structure I could trust.

**How it works.** A 972-line rule file classifies every note into 23 categories using keyword + context + negation logic. The rules live in a plain text file &mdash; when I disagree with a classification, I edit one line and rerun. No server, no API keys, no SaaS dependency: it runs in a browser userscript, exports to Obsidian, and the GitHub repo ships only sanitized data.

[github.com/hazelxu-2003/xhs-knowledge-base](https://github.com/hazelxu-2003/xhs-knowledge-base)

## Research Workbench

**Why I built it.** Existing literature tools (Zotero, Connected Papers, Elicit) each cover one stage. The handoffs between stages &mdash; moving a candidate paper into a reading queue, pulling its PDF, synthesizing across a session, exporting to notes &mdash; are the actual bottlenecks. I wanted one tool that held the whole pipeline.

**How it works.** A six-gate workflow &mdash; idea shaping, deep search, import, close-read, Obsidian, gap analysis &mdash; with each gate holding its own state and composing with the next. Multi-source search (OpenAlex, Semantic Scholar, PubMed) feeds a unified queue; LLM agents generate query families and back-fill records idempotently. API keys live in the browser only &mdash; the server never sees prompts or keys. Zotero integrates two ways: Web API for shared libraries, a local Python bridge for highlights and annotations. The bridge runs on the user's laptop, so the cloud never touches their filesystem.

[github.com/hazelxu-2003/research-workbench-online](https://github.com/hazelxu-2003/research-workbench-online) &middot; [workbench.hazalxu.click](https://workbench.hazalxu.click/)
